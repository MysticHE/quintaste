# Account review corrections — 16 October 2026

Local documentation only. This supersedes the session-refresh claims in the initial account UX acceptance. That acceptance checked server responses and navigation but failed to assert the subscribed account state immediately afterward.

## Five findings resolved

1. **Eligibility:** Better Auth 1.7.10 `hydrateSessionAtom` only fills an empty atom. Custom mutations now call `refreshAccountSession`, which serializes and awaits the subscribed atom's refetch, checks errors and confirms the expected user. Eligibility keeps its successful POST state across refresh failures, clears DOB and retries only the session. The native Google handoff uses the same refresh method.
2. **Offline guest access:** native startup checks the existing cookie through the Expo auth adapter. No session cookie means known guest; storage failures remain unresolved. Web stores only a guest/account routing hint, never credentials or account data. Known guests can mount their local collection without the auth API. An unresolved account can explicitly open the separate guest collection offline while its stored sign-in remains intact. A validated session restores its account scope. This does not authorize cached account identity on a cold offline launch.
3. **Timer isolation:** one module-level coordinator serializes all providers' native notification work. Scope leases and revisions invalidate obsolete work after every await. A native schedule already in flight is cancelled/dismissed before subsequent queued reconciliation proceeds. Disposal cleans the previous owner's scheduled and presented alerts. Account IDs now have distinct notification namespaces; response routing checks the same scope. Legacy profile-scoped alerts are cleared by reconciliation. Native APIs cannot abort an operation already dispatched; compensation and serialization prevent its result from surviving into the new owner's reconciliation.
4. **Profile edits:** a successful custom profile PATCH is followed by the checked session refetch. Me reflects the updated name immediately; a failed refresh leaves the autosave Retry actionable.
5. **Retry accuracy:** global preference Retry is rendered only for explicitly tagged preference load/save failures. Import, sign-out and export errors retain their own operation controls. Successful preference saves/loads clear only their corresponding preference error; they no longer erase unrelated errors. The inline preference status also ignores errors from other operations.
