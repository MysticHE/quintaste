# Finding and checking menu sources

The [per-item source register](../../data/menu-research/menu-item-source-register.json) joins every stored food observation to its source URLs and check dates. It includes published, held and research-only observations. The [branch index](../../data/menu-research/menu-collection-index.json) lists menu coverage and remaining branch gaps; the [per-ID coverage](../../data/menu-research/location-coverage.json) tracks the separate candidate place-ID inventory.

Find an entry in `records` by food name, raw `foodId`, or an app `publicFoodId` together with `publishedMenuIds` and `publicSectionId`. Each entry preserves the exact canonical `dataset`, `menuId` and `foodId`, so its original price, portion, options, verification notes and conflicts can be reopened without guessing which restaurant or menu version supplied it.

Resolve each reference against the register's `sources` array:

| Field | What it establishes |
| --- | --- |
| `sourceRefs` | Sources explicitly attached to the food; if missing, the menu sources, then branch sources. `sourceBasis` states which level was available. A branch-only fallback is a research gap, not item verification. |
| `menuSourceRefs` | Shared menu and ordering context, including channel-specific qualifications. |
| `branchSourceRefs` | Premises, operator and venue eligibility context. These links do not independently prove a particular dish or its ingredients. |
| `url`, `publisher`, `title` | Where the observation came from and which page to revisit. |
| `checkedAt`, `dateBasis` | Saved source check date, or saved retrieval date when no check date exists. Missing dates stay null; malformed dates stop generation. |
| `publishedAt` | The source's stated publication date, when recorded. This is separate from our retrieval date and does not prove that prices are still current. |
| `accessStatus` | Whether the page was readable, blocked, historical or otherwise qualified at collection. |

`state: published` means that a food observation is present in the current locally approved app menu projection. It does not certify ingredients, current stock or future prices. `held` observations retain unresolved description, identity, availability or date conflicts. Other unpublished source facts remain `research-only`. Where the source does not print a current price or currency, the app retains that uncertainty. The original dataset contains the detailed reason and any verified/unverified field lists.

Counts distinguish stored source observations from public occurrences. A shared brand food can appear at several branches, while different ordering channels can repeat a dish. `sourceDocuments` counts dataset/source-ID observations; `uniqueSourceUrls` counts distinct URLs. Neither is a count of independently verified restaurants or unique dishes.

Rebuild in order after a reviewed change: `scripts/build-menu-research-index.ts`, `scripts/build-menu-coverage.ts`, `scripts/sync-researched-menus.ts --approve-reviewed`, then `scripts/build-menu-source-register.ts`. Then run `scripts/build-venue-catalogue.ts --write` to regenerate the compact browse index from approved summaries, explicit venue claims and reviewed coordinates. Run the publication, source-register and venue-catalogue scripts with `--check` to detect publication or traceability drift. Use the project's configured TypeScript runner. Generation fails if a published food lacks its exact research row, a source URL cannot resolve, normalized IDs collide, or source-food totals differ from the research inventory. Dataset fingerprints bind the register to the exact research files used to build it.

For an unclear food, search its exact merchant name, premise and item name online. Prefer current operator menus and merchant-managed ordering details; use dated photographs or independent accounts as corroboration. Preserve every material source URL, retrieval/check date, what it establishes, and remaining conflicts in the canonical packet. Keep channel prices and old observations separate. Do not infer vegan status from a vegetarian venue or infer actual meat from a generic delivery-platform description. Unresolved claims remain held or explicitly unknown.

The register is a local build/research artifact and is not uploaded in the release or downloaded in the mobile menu payload. Reviewed source URLs and qualifications are compiled into published menus. Raw page captures and retrieval manifests in local QA folders support the audit; the canonical URLs and record identifiers are the durable way to find the source again.
